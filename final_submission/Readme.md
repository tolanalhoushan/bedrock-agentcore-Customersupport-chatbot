# Customer Support Chatbot with Amazon Bedrock AgentCore

## 1. Project Overview
This project implements a production-grade customer support chatbot for a fictional online store using the Amazon Bedrock AgentCore managed harness and Amazon Nova Pro (`us.amazon.nova-pro-v1:0`). The chatbot classifies incoming customer requests into three distinct categories:
- **Bug Reports**: Collects required parameters (`description`, `stepsToReproduce`, `environment`) and executes the `bugreports___create_bug_report` tool via AgentCore Gateway once all fields are collected.
- **Platform Questions**: Answers queries strictly grounded in the embedded shop FAQ (`online_shop_faq.md`).
- **Other Requests**: Redirects unsupported, off-topic, or out-of-scope queries to human phone support at `1-800-555-0199 (Monday–Friday)`.

## 2. Prompt Engineering & Iteration Journey
Achieving strict behavior alignment across all 11 harness evaluation test cases required targeted refinements in `system_prompt.txt`:

### Key Challenges & Fixes
1. **Tool Invocation Gating & Parameter Validation**:
   * *Issue*: The model tended to hallucinate ticket IDs or trigger `bugreports___create_bug_report` even when parameters like `stepsToReproduce` or `environment` were missing.
   * *Fix*: Implemented strict parameter gating that forbids tool execution or ticket ID creation unless all three fields (`description`, `stepsToReproduce`, `environment`) are explicitly provided in the current turn.

2. **Single-Question Follow-Up Hierarchy**:
   * *Issue*: When multiple details were missing, the model asked for all missing parameters simultaneously or varied its question order.
   * *Fix*: Established an explicit single-field priority evaluation chain (`description` → `stepsToReproduce` → `environment`) to ensure exactly one focused follow-up question is asked per turn.

3. **Suppressing `<thinking>` Tags & Reasoning Output**:
   * *Issue*: Nova Pro emitted internal chain-of-thought `<thinking>` XML blocks in customer-facing outputs.
   * *Fix*: Added a top-level zero-tolerance rule in `system_prompt.txt` strictly prohibiting reasoning tags or XML markup.

4. **Off-Topic & Out-of-Scope Redirection**:
   * *Issue*: For off-topic requests (e.g., product recommendations, gift cards, weather, unlisted compensation policies), the model attempted to be helpful or invented policies.
   * *Fix*: Enforced strict fallback routing so that all `OTHER` queries or missing FAQ policies resolve directly to the phone support hand-off string: `Please contact human support by phone for assistance with this request.`

## 3. Tool Integration & DynamoDB Persistence
- **Tool Name**: `bugreports___create_bug_report`
- **Infrastructure**: AWS Lambda integrated via AgentCore Gateway, persisting valid bug reports directly into the `bug-report-tool-stack-bug-reports` DynamoDB table.
- **Behavior**: Real UUID ticket IDs generated by the Lambda function are returned to the user upon successful tool execution.

- **Submission Deliverables**: All required files (`system_prompt.txt`, `agentcore_config.json`, `harness-tests.json`, `output_eval_dataset.jsonl`, `README.md`) packaged into `final_submission.zip`.
